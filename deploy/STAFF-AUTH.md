# Staff authentication and shared provider key

Studio uses Cloudflare Access email OTP with the existing reusable Email policy.
In STAFF_AUTH_MODE=cloudflare, staff do not enter or store provider credentials.
Every API request validates the Access JWT signature, issuer, audience, lifetime
and staff identity. Mutating requests require the configured public Origin.
A fixed-origin server proxy injects only the server MuAPI key and content headers;
Access tokens and cookies never go to MuAPI. Key/account administration is not
exposed by the media API allowlist. There are no local models.

## Install or rotate the key

Create a production API key at https://muapi.ai/dashboard under API Keys.
Production generation consumes the MuAPI account's credits. Sandbox keys return
mock results and are suitable for testing. No key has been generated by this deployment.

First install the included deploy/set-muapi-key.py as /usr/local/sbin/studio-set-muapi-key
on the app host (root-owned, mode 0700). Then run from your machine:

    ssh -t root@YOUR_STUDIO_HOST /usr/local/sbin/studio-set-muapi-key

The command prompts without echo and updates
/opt/open-generative-ai/secrets/muapi_api_key. It does not put the key in command
history or logs. The host directory is root-only; the file is root:1000 0440
and mounted read-only into the unprivileged app. The backend reads it on each
request, so reload Studio after installing/rotating; no restart is needed.
Do not paste keys into chat, browser settings, Git, or NEXT_PUBLIC variables.
An encrypted backup may be retained in the existing approved secret store.

Nonsecret staff configuration: /opt/open-generative-ai/secrets/staff.env.
Storage credentials remain in the separate storage.env and are unchanged.
Missing provider key: verified staff see an administrator setup notice;
provider requests return 503. Invalid Access JWT returns 401 even on localhost.

See MEDIA-STORAGE.md for permanent media links and the archive timer.

## Workspace behavior

The provider account, provider history, balance, and generated resources are
shared by allowed staff. This deployment does not add per-staff billing or
resource isolation. Browser drafts are scoped by staff email. New archived
videos use a stable team namespace independent of provider-key rotation;
existing signed-capability media links remain valid. The private S3 bucket
and its signing secret must be preserved.

## Verification

Run node tests/staffAuth.test.mjs, node tests/staff-client.test.mjs,
node tests/videoStorage.test.cjs, npm run build:packages, and npm run build.
Provider/JWT tests use synthetic keys; no paid generation is needed.
Actual Cloudflare OTP delivery and real provider generation require an
allowlisted staff member and an installed MuAPI key.
